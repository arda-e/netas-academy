# Blog Posts Search Implementation

## Goal

Add server-side text search to the blog posts (`/blog-yazilari`) page, reusing the URL-based search pattern from the courses page (`SearchField`), with a `searchOnly` flag to suppress additional filter UI.

## Key Findings from Exploration

| Aspect | Current State |
|---|---|
| Blog search | Client-side only (`BlogSearch`) — filters by title, no URL params |
| Courses search | `SearchField` component — uses `?search=` URL param, server reads it |
| Events page | No search bar (only type pills + sort) |
| Strapi blog-post | `title`, `excerpt`, `content`, `sourceNotes` text fields; `$containsi` filter available |
| `getBlogPosts()` | No search parameter; fetches all 100 posts |

## Implementation Plan

### 1. Update `getBlogPosts()` in `frontend/src/lib/strapi.ts`
- Add optional `search?: string` parameter
- When `search` is provided, append Strapi `filters[$or]` with `$containsi` on `title`, `excerpt`, and `content` fields (NOT `sourceNotes`)

### 2. Extract shared search component — `SearchField` → shared location
- Move/copy `SearchField` from `frontend/src/components/courses/course-catalog-list.tsx` to `frontend/src/components/content/search-field.tsx` (alongside other shared content components)
- Add `searchOnly?: boolean` prop (default `true` for blog usage; the component is already search-only by design)
- Keep URL-based `?search=` pattern via `useRouter`/`useSearchParams`

### 3. Update blog page (`frontend/src/app/blog-yazilari/page.tsx`)
- Read `searchParams.search` from page props
- Pass `search` to `getBlogPosts()`
- Replace `BlogSearch` client component with `SearchField` component
- Keep `BlogList` for rendering (pass filtered posts directly from server)
- Remove `src/app/blog-yazilari/blog-search.tsx` since it's no longer needed

### 4. (Optional) Refactor courses page to use shared `SearchField`
- Import `SearchField` from the new shared location instead of local definition

## Files to Change

1. **`frontend/src/lib/strapi.ts`** — add `search` param to `getBlogPosts()`, append `filters[$or]` query
2. **`frontend/src/components/content/search-field.tsx`** — extract `SearchField` to shared location, add `searchOnly` prop
3. **`frontend/src/app/blog-yazilari/page.tsx`** — use `SearchField` + server-side filtering, remove `BlogSearch` usage
4. **`frontend/src/app/blog-yazilari/blog-search.tsx`** — delete (no longer needed)
5. **`frontend/src/components/courses/course-catalog-list.tsx`** — update import to use shared `SearchField` (optional refactor)

## Tests/Validation

- `npm run lint` and `npm run build:frontend` 
- Manually verify:
  - Blog page loads all posts with no search param
  - Typing in search input updates URL `?search=...`
  - Search filters posts by title, excerpt, and content (server-side)
  - Empty results show the "no results" message
  - Turkish characters in search work correctly

## Risks

- **Low risk**: Strapi `$containsi` is case-insensitive on SQLite (default backend), but may need `$containsi` vs `$contains` depending on Strapi version
- **Low risk**: The `SearchField` component uses `useRouter` from `next/navigation` — the blog page must remain a server component; the search field will be a client component embedded in the server page (same pattern as courses page)
