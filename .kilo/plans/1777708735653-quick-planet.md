# P5-02: Consolidate shared utilities and error handling across frontend/backend

## 1. Goal

Eliminate duplicated business logic between frontend and backend stacks by:
- Making the backend the single source of truth for event registration window logic via a new `GET /api/events/:documentId/registration-status` endpoint
- Creating shared controller helper utilities (`formatError`, `formatSuccess`, `validateBody`) for all 4 custom backend controllers
- Consolidating 8 duplicate `Intl.DateTimeFormat('tr-TR')` instances into a single shared frontend utility
- Adding try-catch error handling to the 2 frontend API proxy routes that currently lack it

## 3. Proposed implementation

### Phase 1: Shared controller helpers (backend)

**Create `backend/src/utils/controller-helpers.ts`** with three exports:

```ts
// formatError — consistent error response
function formatError(message: string, status = 400): { error: string; status: number }

// formatSuccess — consistent success wrapper
function formatSuccess(data: unknown): { data: unknown }

// validateBody — declarative required-field checking
// Returns null if valid, or an error object to set on ctx.body
function validateBody(
  body: Record<string, unknown>,
  requiredFields: string[]
): { error: string; status: number } | null
```

**Update all 4 custom controllers** to use these helpers:
- Replace `throw new ValidationError('…')` patterns with `ctx.body = formatError('…', 400); ctx.status = 400; return;`
- Replace `ctx.body = { data: result }` with `ctx.body = formatSuccess(result)`
- Replace manual required-field checks with `validateBody(ctx.request.body, [...])`

**Files to modify:**
- NEW: `backend/src/utils/controller-helpers.ts`
- `backend/src/api/registration/controllers/registration.ts`
- `backend/src/api/contact-submission/controllers/contact-submission.ts`
- `backend/src/api/course-application/controllers/course-application.ts`
- `backend/src/api/analytics-event/controllers/analytics-event.ts`

### Phase 2: Registration status endpoint (backend + frontend)

**Backend — new endpoint `GET /api/events/:documentId/registration-status`:**

1. Add route in `backend/src/api/event/routes/custom-event.ts`

**Frontend — call API instead of local computation:**

## 6. Risks and open questions

| Risk | Mitigation |
|------|------------|
| **Async registration check may cause waterfall** | Both pages already `await getEventBySlug()` — the `getEventRegistrationStatus` call can be fired in parallel using `Promise.all()` |
| **Frontend strapi.ts error swallowing** | If `getEventRegistrationStatus` returns `null` (API unreachable), pages default `registrationOpen = false`. This is safe (closed is more conservative than open) |
| **Controller error format change is breaking** | Frontend API proxy routes pass through whatever Strapi returns. Changing from Strapi's native error format to `{ error, status }` may affect the proxy responses. The frontend forms (`use-event-registration-form`, `intent-lead-form`) parse error responses — verify they handle the new format. The `formatError`/`formatSuccess` helpers should NOT change the HTTP status code behavior — only the response body shape should be consistent |
| **Test file source-level assertions** | `event-detail-source.test.mjs` does source-level regex matching. Must update to match new import/call patterns. This test is fragile but required |
| **Date format differences** | Blog uses `day: 'numeric'`, news uses `day: '2-digit'`. With Turkish locale, both produce identical numeric output. Verify with `new Intl.DateTimeFormat('tr-TR', { day: 'numeric' }).format(new Date())` vs `{ day: '2-digit' }` — if identical, one `formatLongDate` function suffices. If different, add a parameter or separate export |

### Design decision

**`formatError` return behavior:** `formatError` sets `ctx.body` and the controller sets `ctx.status` and returns (does not throw). This prevents Strapi's error middleware from wrapping the response again with its own error format. Controllers will follow this pattern:

```ts
const err = validateBody(ctx.request.body, ['eventDocumentId', 'student']);
if (err) {
  ctx.body = err;
  ctx.status = err.status;
  return;
}
```
