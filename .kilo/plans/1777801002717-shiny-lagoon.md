## 3. Proposed Implementation

### 3.1 Target module architecture

```
frontend/src/lib/
├── strapi.ts                 → REMOVED (or kept as barrel temporarily)
├── strapi-types.ts           ← NEW: all type definitions
├── strapi-client.ts          ← NEW: fetchStrapi, STRAPI_URL
├── strapi-media.ts           ← NEW: media URL utilities
├── strapi-courses.ts         ← NEW: course fetch functions
├── strapi-events.ts          ← NEW: event fetch functions + normalizeEventType
├── strapi-blog.ts            ← NEW: blog fetch functions
└── strapi-teachers.ts        ← NEW: teacher fetch functions
```

### 3.2 Module dependency graph

```
strapi-types.ts          (no deps)
    ├── strapi-client.ts     → strapi-types.ts
    ├── strapi-media.ts      → strapi-types.ts
    ├── strapi-courses.ts    → strapi-types.ts, strapi-client.ts

    ├── strapi-blog.ts       → strapi-types.ts, strapi-client.ts
    └── strapi-teachers.ts   → strapi-types.ts, strapi-client.ts
```

## 4. Implementation Phases

### Phase A: Create all 7 new module files

**Input**: Monolithic `strapi.ts` content
**Output**: 7 new files in `frontend/src/lib/`, each ≤200 lines
**Dependencies**: None
**Parallelizable**: No (but the 7 files can be created in any order, extracted mechanically from the monolith)

**Sub-tasks**:
1. Create `strapi-types.ts` — extract lines 1-150 (types only)
2. Create `strapi-client.ts` — extract `fetchStrapi` + `STRAPI_URL`
3. Create `strapi-media.ts` — extract `getNestedString`, `toStrapiAssetUrl`, `getStrapiMediaUrl`, `getStrapiMediaAltText`
4. Create `strapi-courses.ts` — extract `getCourses`, `getCourseSlugs`, `getCourseBySlug`, `getLatestCourses`
5. Create `strapi-events.ts` — extract `normalizeEventType`, `getEvents`, `getEventSlugs`, `getEventBySlug`, `getEventRegistrationStatus`
6. Create `strapi-blog.ts` — extract `getBlogPosts`, `getBlogPostSlugs`, `getBlogPostBySlug`
7. Create `strapi-teachers.ts` — extract `getTeachers`, `getTeacherSlugs`, `getTeacherBySlug`

**Key considerations**:
- All function bodies are copied verbatim — NO behavior changes
- `normalizeEventType` is placed in `strapi-events.ts` (it's a runtime function, not a type) but remains exported since `etkinlikler/page.tsx` imports it
- `getNestedString` stays private (unexported) in `strapi-media.ts`
- Cross-module imports: domain modules import `fetchStrapi` from `./strapi-client` and types from `./strapi-types`

### Phase B: Convert `strapi.ts` to a re-export barrel (safety net)

**Input**: Phase A complete
**Output**: `strapi.ts` now re-exports everything from the 7 new modules
**Purpose**: Ensures zero breakage of any consumer during the transition

```typescript
// strapi.ts → barrel re-export (temporary)
export { type StrapiCourse, type StrapiEvent, type StrapiBlogPost, /* ... */ } from './strapi-types';
export { type StrapiEventType, type StrapiEventSortOrder, type EventRegistrationStatus } from './strapi-types';
export { fetchStrapi } from './strapi-client'; // (if ever publicly needed)
export { toStrapiAssetUrl, getStrapiMediaUrl, getStrapiMediaAltText } from './strapi-media';
export { getCourses, getCourseSlugs, getCourseBySlug, getLatestCourses } from './strapi-courses';
export { normalizeEventType, getEvents, getEventSlugs, getEventBySlug, getEventRegistrationStatus } from './strapi-events';
export { getBlogPosts, getBlogPostSlugs, getBlogPostBySlug } from './strapi-blog';
export { getTeachers, getTeacherSlugs, getTeacherBySlug } from './strapi-teachers';
```

## 5. Edge Cases & Risks

| Risk | Likelihood | Mitigation |
|------|-----------|------------|
| Missed consumer import breaks build | Low | Phase B barrel ensures backward compat; Phase E build catches any missed files |
| Test source paths break | High | Phase D updates paths explicitly; alternatively defer to P7-04 |
| `normalizeEventType` placement confusion | Low | Placed in `strapi-events.ts` (it's runtime logic, not a type) — documented explicitly |
| `getNestedString` accidentally exported | Low | Keep as non-exported function in `strapi-media.ts` |
| Import path autocomplete break in IDE | Medium | Temporary — resolved after Phase E when old `strapi.ts` is removed |
| Type re-exports cause `isolatedModules` issues | Low | Using `export type` syntax prevents runtime emit issues |
| `StrapiMedia` type not exported separately | Low | It's in `strapi-types.ts` and imported internally by media module + types that reference it |

## 6. Task Dependency Graph

```
Phase A (create 7 modules) → sequential (any order, but must complete before B)
    ↓
Phase B (barrel file) → after A
    ↓
Phase C (update 14 consumers) → after B; ALL 14 files can be updated IN PARALLEL
    ↓
Phase E (remove barrel) → after C + build verification
    ↓
Phase D (update tests) → can run in parallel with C, or after E
    ↓
Phase F (validation) → after C, D, E
```

**Maximum parallelism**: Phase C allows 14 files updated simultaneously by different developers (or batched by an automated tool).

---

## 7. Rollback Plan

If any issue is discovered during Phase C:
1. The barrel file (`strapi.ts`) in Phase B serves as a safety net — all original imports still work
2. Revert individual consumer changes one at a time
3. If widespread issues, revert all Phase C changes and keep the barrel architecture as the final state
