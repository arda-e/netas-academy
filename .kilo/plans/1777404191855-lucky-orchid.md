## Fix 1: Add unique constraint on email field

**File:** `backend/src/api/newsletter-subscription/content-types/newsletter-subscription/schema.json`

**Change:** Add `"unique": true` to the email attribute to prevent race-condition duplicates.

**Before:**
```json
"email": {
  "type": "email",
  "required": true
}
```

**After:**
```json
"email": {
  "type": "email",
  "required": true,
  "unique": true
}
```

**Rationale:** The `findOne → create` pattern in the service is not atomic. Concurrent requests for the same email could create duplicate records. Adding `unique: true` enforces the constraint at the database level (Strapi adds a unique index on the email column).

**⚠️ Note:** After changing the schema, you must run `npm run build:backend` and restart. Strapi 5 will attempt to apply the unique constraint on SQLite. If there are already duplicate emails in the database, the migration will fail — deduplicate the data first.

## Fix 2: Preserve original subscribedAt on reactivation

**File:** `backend/src/api/newsletter-subscription/services/newsletter-subscription.ts`

**Change:** Remove the `subscribedAt: now` line from the reactivation update block (the block that reactivates passive/unsubscribed subscriptions). The original `subscribedAt` should reflect when the user first subscribed, not when they reactivated.

**Location:** Line ~75, inside the `data:` object of the reactivation `update()` call:

**Before (excerpt):**
```ts
data: {
  status: 'active',
  lastSeenAt: now,
  subscribedAt: now,     // ← REMOVE THIS LINE
  sourcePage: input.sourcePage || null,
  sourceContentType: input.sourceContentType || null,
  sourceContentSlug: input.sourceContentSlug || null,
},
```

**After (excerpt):**
```ts
data: {
  status: 'active',
  lastSeenAt: now,
  sourcePage: input.sourcePage || null,
  sourceContentType: input.sourceContentType || null,
  sourceContentSlug: input.sourceContentSlug || null,
},
```

**Rationale:** `subscribedAt` tracks the original subscription timestamp. Overwriting it on reactivation loses historical data. The existing test for passive reactivation (service.test.ts) will also need updating to no longer expect `subscribedAt` in the update data for that path.
