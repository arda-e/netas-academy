## Goal

Give content admins the ability to send custom HTML emails to event participants and receive automatic confirmation emails on registration — all from the Event detail page in the Strapi admin, without using external email tools.

## Architecture Overview

A new Strapi 5 local plugin (`backend/src/plugins/iletisim-merkezi/`) with:

- **Server-side:** services for sending admin-configured emails and managing the global confirmation template
- **Admin-side:** React components injected into the Event admin detail view's injection zone
- **Lifecycle integration:** an after-registration hook for auto-confirmation

The existing `internal-notifications` plugin handles internal admin notifications and is NOT modified. The new plugin handles student-facing event emails.

## Existing State (verified)

- Event schema already has `meetingLink` (string) and `autoConfirmationEnabled` (boolean, default false)
- Registration schema already has `lastEmailSentAt` (datetime)
- `event/services/event.ts` has `sendRegistrationEmail()` — sends to filtered registrants via `sendTemplatedEmail`
- `event/controllers/event.ts` has `sendRegistrationEmail` and `registrationStatus` endpoints
- `registration/services/registration.ts` wraps registration in transaction, fires `internal-notifications` after commit (fire-and-forget pattern)
- `registration/lifecycles.ts` has `beforeCreate` duplicate check only. No `afterCreate` hook
- Registered route: `POST /api/registrations/register` (auth: false)

## Implementation Units

### Unit 1: Confirmation Template Storage (R4)

Create plugin skeleton and a single type for the global confirmation template.

**New files:**

| File | Purpose |
|---|---|
| `backend/src/plugins/iletisim-merkezi/strapi-server.ts` | Plugin entry — registers content-types, services, bootstrap |
| `backend/src/plugins/iletisim-merkezi/server/register.ts` | Extends registration lifecycle to add afterCreate hook |
| `backend/src/plugins/iletisim-merkezi/server/bootstrap.ts` | Seeds default confirmation template on first install |
| `backend/src/plugins/iletisim-merkezi/server/content-types/confirmation-template/schema.json` | Strapi single type: htmlBody (text), enabled (boolean, default true) |
| `backend/src/plugins/iletisim-merkezi/server/services/template-service.ts` | get / update / reset template |

**What it does:**
- Registers a Strapi single type (confirmation-template) accessible via the admin content manager
- Bootstrap seeds a sensible Turkish default template
- Template variables: `{{ event.title }}`, `{{ event.startsAt }}`, `{{ event.location }}`, `{{ event.meetingLink }}`

**Decision:** Single type over plugin config because non-technical admins manage it through built-in UI without code changes.

### Unit 2: Auto-Confirmation on Registration (R3, R4, F1)

**New files:**

| File | Purpose |
|---|---|
| `backend/src/plugins/iletisim-merkezi/server/services/confirmation-service.ts` | sendAutoConfirmation(registrationId) — load registration + event + template, substitute variables, send email, update lastEmailSentAt |
| `backend/src/plugins/iletisim-merkezi/server/services/utils/template.ts` | String replacement: replaceTemplateVariables(html, event) |

**Hook registration (in server/register.ts):**
- Uses `strapi.db.lifecycles.subscribe({ model: 'api::registration.registration', afterCreate: ... })`
- Checks `event.autoConfirmationEnabled`
- Calls `sendAutoConfirmation(registrationId)` with fire-and-forget (catch-log, never throw)

**Fire-and-forget pattern:**
- After registration.create completes, invoke the service without await
- Errors are logged via strapi.log.error

**What changes to existing behavior:**
- Before: registration creates + internal-notification to admins
- After: same + optional student-facing email if event.autoConfirmationEnabled

### Unit 3: Manual Email API Endpoint (R5–R10, F2)

**New files:**

| File | Purpose |
|---|---|
| `backend/src/plugins/iletisim-merkezi/server/services/manual-email-service.ts` | sendManualEmail(eventDocId, subject, htmlBody, statuses) — fetch event + registrations, filter, dedup (R10), append meeting link (R7), send, update lastEmailSentAt, return summary |
| `backend/src/plugins/iletisim-merkezi/server/controllers/manual-email-controller.ts` | send(ctx) and sendTest(ctx) |
| `backend/src/plugins/iletisim-merkezi/server/routes/manual-email-routes.ts` | POST /iletisim-merkezi/events/:documentId/send-manual-email (authenticated admin), POST /iletisim-merkezi/events/:documentId/send-test-email (authenticated admin) |

**sendManualEmail flow:**
1. Fetch event with registrations populated (populate student)
2. Filter registrations by status (default if absent: ['confirmed'])
3. Deduplicate by student email (R10)
4. Append meeting link to htmlBody if event.meetingLink exists (R7)
5. Send via strapi.plugin('email').service('email').send() — plain send, no template variables
6. Update lastEmailSentAt on each sent registration
7. Return { attemptedRecipients, sentRecipients, skippedRecipients, failedRecipients }

**sendTestEmail flow:**
- Same as sendManualEmail but sends only to the admin's own email
- Responds with test result — no registration updates

## Risks & Mitigations

| Risk | Impact | Mitigation |
|---|---|---|
| Strapi 5 admin injection API changed | Unit 4 blocked | Fall back to custom field injection or plugin-level admin page |
| Email provider not configured | Auto-confirmation silently fails | Fire-and-forget logs to Strapi log |
| Lifecycle API registration from plugin for core CT | Hook may not fire | Register in strapi-server.ts bootstrap, verify against Strapi 5 lifecycle API |
| Template HTML with CSS classes breaks in email clients | Poor rendering | Admin designs externally; no inlining in MVP |

## Rollback

- Comment out `'iletisim-merkezi': { enabled: true }` in `backend/src/config/plugins.ts`
- Existing API endpoints and registration flow work without the plugin
- Schema additions (meetingLink, autoConfirmationEnabled) are additive and backward-compatible
