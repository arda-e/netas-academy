# Plan: Remove S3 upload config and revert to local uploads

## Goal

Remove all AWS S3-related configuration, dependencies, and environment variables from the monorepo. Revert to Strapi's built-in local upload provider (`@strapi/provider-upload-local`), which is already included as a transitive dependency of `@strapi/upload`.

## Files to change

### 1. `backend/config/plugins.ts` — Remove S3 upload conditional block

**Current behavior:** Lines 4–40 read four AWS env vars and conditionally configure the `aws-s3` upload provider. Line 43 spreads `...upload` into the returned config object. When env vars are absent, `upload` is `{}` (local fallback).

**Change:**
- Delete lines 3–40 (the `s3` variable declarations and the `upload` ternary).
- Delete the `...upload` spread on line 43.
- The return block should directly start with `email:` — no upload config at all (Strapi falls back to local automatically).

**After change, the file should look like:**
```ts
import type { Core } from '@strapi/strapi';

const config = ({ env }: Core.Config.Shared.ConfigParams): Core.Config.Plugin => {
  return {
    email: {
      config: {
        provider: env('EMAIL_PROVIDER', 'sendmail'),
        providerOptions: {},
        settings: {
          defaultFrom: env('EMAIL_DEFAULT_FROM', 'Netas Academy <no-reply@netas-academy.local>'),
          defaultReplyTo: env('EMAIL_DEFAULT_REPLY_TO', 'support@netas-academy.local'),
          testAddress: env('EMAIL_TEST_ADDRESS', 'test@netas-academy.local'),
        },
      },
    },
    'csv-exporter': {
      enabled: true,
      config: {},
    },
    'internal-notifications': {
      enabled: true,
      resolve: './src/plugins/internal-notifications',
      config: {},
    },
  };
};

export default config;
```

### 2. `backend/package.json` — Remove S3 provider dependency

- **Line 24:** Remove `"@strapi/provider-upload-aws-s3": "^5.44.0"` (and the trailing comma on line 23 if needed for valid JSON).

### 3. `docker-compose.yml` — Remove AWS and MEDIA_* env vars

- **Delete lines 26–34** (all `AWS_*`, `MEDIA_PUBLIC_URL`, and `MEDIA_ROOT_PATH` environment variables).
- The uploads volume mount on line 37 (`./.docker-data/uploads:/app/backend/public/uploads`) stays — it's needed for local upload persistence in Docker.

### 4. `frontend/next.config.ts` — Replace S3 default for `mediaPublicUrl`

**Current:** Line 6 hardcodes the S3 bucket URL as the fallback when `MEDIA_PUBLIC_URL` is not set.

**Change:**
- Replace lines 4–6:
  ```ts
  const mediaPublicUrl =
    process.env.MEDIA_PUBLIC_URL ??
    "https://netas-academy-media-540713960950-eu-central-1.s3.eu-central-1.amazonaws.com";
  ```
  with:
  ```ts
  const mediaPublicUrl = process.env.MEDIA_PUBLIC_URL ?? strapiUrl;
  ```
  (`strapiUrl` is already defined on line 3 as `http://127.0.0.1:1337`.)
- This causes `getStrapiImageRemotePatterns()` to use the Strapi server as the image origin, which is the correct behavior for local uploads served via Strapi's `/uploads/` path.

### 5. Post-change cleanup

After editing the files, run from the repo root:
```bash
npm install             # regenerates package-lock.json without the S3 provider
npm run build:backend   # verifies backend compiles
npm run build:frontend  # verifies frontend compiles
npm run lint            # verifies no lint issues
```

## Risks

1. **Existing media data:** Any uploads previously stored in S3 will no longer be served via the S3 URL. Existing Strapi database records may still reference S3 URLs for old media — those will break unless media is re-uploaded locally.
2. **Docker volume:** The Docker compose already mounts `./.docker-data/uploads:/app/backend/public/uploads` — make sure this directory exists or is created during deployment.
3. **No production S3 config:** The `.env` files have no S3 vars set, and the `plugins.ts` conditional already falls back to local — meaning the current dev setup already uses local uploads. Production may have been using S3 via Docker env vars; that would break after this change unless uploads are migrated.
